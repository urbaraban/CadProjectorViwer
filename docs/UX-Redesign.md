# 2Cut — ревью UI/UX и план редизайна оболочки

Область: `src/CadProjector.App` (Avalonia 12.1.2, FluentTheme, CommunityToolkit.Mvvm).
Основной объект правки: `Views/MainWindow.axaml` (817 строк) и связанное с ним состояние в
`ViewModels/MainViewModel.cs`.

Документ состоит из трёх частей: **ревью текущего состояния** (что и почему сломано),
**целевой дизайн** (как должно быть) и **пошаговый план** (9 фаз, каждая компилируется и
запускается самостоятельно).

---

## Часть 1. Ревью текущего состояния

### 1.1. Тулбар: 24 контрола в одной нерасширяемой строке

`MainWindow.axaml:38-86` — весь верх это один `StackPanel Orientation="Horizontal"` внутри
`Grid ColumnDefinitions="Auto,*"`, где панель кнопок лежит в колонке `Auto`.

Что в нём лежит подряд, без единого разделителя по смыслу:

```
Бренд · Открыть · Очистить · Загрузить · Сохранить · Экспорт .ild · Отмена · Пуск · Стоп ·
чип связи · ↶ · ↷ · Маска · Сетка · Объекты · Сцена · 3D · Выравнивание STL · Трансформ ·
Калибровка · Устройства · Рабочая папка · Автоматизация · Логи · Клавиши · RU
```

Проблемы:

| # | Проблема | Следствие |
|---|----------|-----------|
| A | Смешаны 6 разных категорий: файловые операции, транспорт лазера, история, режимы вида, панели, настройки | Нет мышечной памяти, каждый раз читаешь все 24 подписи |
| B | Колонка `Auto` + `StackPanel` без переноса и без overflow-меню | При ширине окна ниже ~1900 px правый край **обрезается молча**: на 1366×768 «Логи», «Клавиши» и переключатель языка физически недоступны |
| C | `StatusText` (`:83-85`) лежит в колонке `*` справа от разросшейся `Auto`-колонки | Схлопывается в ноль первым; статус приложения де-факто невидим |
| D | «Пуск» и «Стоп» стоят вплотную к «Очистить» и «Экспорт» | Опасная операция (вывод лазера) на расстоянии одного промаха от рутинной |
| E | 9 кнопок (`Объекты`, `Сцена`, `Устройства`, `Трансформ`, `Калибровка`, `Рабочая папка`, `Автоматизация`, `Логи`, `Выравнивание STL`) — это `Button`, но команды под ними делают `IsXOpen = !IsXOpen` (`MainViewModel.cs:679-684`) | Тоггл без визуального состояния: по кнопке не видно, открыта панель или нет. Рядом `Маска`/`Сетка`/`3D` — честные `ToggleButton`. Два разных поведения в одном ряду |
| F | Пара «Экспорт .ild» / «Отмена» подменяют друг друга по `IsBusy` (`:46-49`) | Кнопки под курсором «прыгают» — соседние элементы уезжают влево-вправо во время импорта |

### 1.2. Оверлеи: 10 плавающих панелей в одном `Grid`, координаты захардкожены

`MainWindow.axaml:107-839`. Каждая панель — `Border` с фиксированной привязкой к углу и
`Margin="12"`. Позиции никто не согласовывает.

|--------|--------|--------|--------|--------|--------|--------|
| Объекты | Left | Stretch | 300 | — | 10 | 132 |
| Сцена | Left | Top | 300 | Max 780 | 10 | 181 |
| Калибровка | Left | Top | 320 | — | 10 | 393 |
| Логи | Left | Center | 480 | 280 | 10 | 742 |
| Выравнивание STL | Right | Top | 420 | Max 720 | **11** | 234 |
| Трансформ | Right | Top | 300 | — | 10 | 332 |
| Устройства | Right | Stretch | 420 | Max 740 | 10 | 415 |

| Клавиши | Right | Center | 420 | 560 | 10 | 774 |

Отсюда:

- **Четыре панели претендуют на левый верхний угол** (Объекты, Сцена, Калибровка) и ещё одна на
  левый центр (Логи, шириной 480 — перекрывает все три).
- **Шесть панелей претендуют на правую сторону**, четыре из них — на правый верхний угол.
- У девяти панелей `ZIndex="10"`, то есть порядок наложения определяется **порядком объявления в
  XAML**, а не логикой. Это не настраивается и неочевидно при чтении.
- **Реальный баг, воспроизводится всегда:** `MainViewModel.cs:1615` автоматически ставит
  `IsTransformOpen = true` при выборе объекта. Панель «Трансформ» (Right/Top, 300) объявлена в
  XAML *раньше* панели «Устройства» (Right/Stretch, 420). Значит при открытом хабе устройств
  выбор объекта на столе открывает «Трансформ» **полностью под** «Устройствами» — пользователь
  видит, что ничего не произошло.
- **Второй сценарий:** `OpenCalibrate` (`MainViewModel.cs:741-753`) и `SelectMeshModule`
  (`:763-787`) принудительно ставят `IsDevicesOpen = true`. То есть код сам создаёт ситуацию с
  двумя-тремя одновременно открытыми панелями, ни разу не проверяя, во что они упрутся.
- Панель прогресса с `ZIndex="20"` и `VerticalAlignment="Bottom"` растянута на всю ширину и
  перекрывает низ панели «Объекты» (у неё `VerticalAlignment` по умолчанию = Stretch) и подсказку
  3D-вида (`:126-129`).
- Панели нельзя ни подвинуть, ни отресайзить, ни закрепить. Состояние не переживает перезапуск.
- Закрытие только по крестику. `Esc` не закрывает ничего (`MainWindow.axaml.cs:170-175` — только
  отмена захвата хоткея; `:149-154` — только очистка фильтра в рабочей папке).

### 1.3. Фиксированные размеры ломаются на реальных экранах

`Height="520"` (рабочая папка), `Height="560"` (клавиши), `MaxHeight="780"` (сцена),
`MaxHeight="740"` (устройства). Клиентская область на ноутбуке 1366×768 — около 700 px.
Панель «Сцена» с `MaxHeight="780"` не помещается: её `ScrollViewer` обрежется по границе окна, а
нижние поля («Проекторы сцены») окажутся недостижимы, потому что скроллится внутренний
`ScrollViewer`, а не обрезанный `Border`.

### 1.4. Ноль дизайн-токенов: 60+ хардкод-цветов

По всему `MainWindow.axaml`: `#1E1E1E`, `#E61E1E1E`, `#555`, `#F0F0F0`, `#8CF`, `#F66`, `#AAA`,
`#888`, `#CCC`, `#FC8`, `#EEE`, `#666`, `#2A2A2A`, `#22FFFFFF`, `#5A1C1C`, `#F01A1A1A`.
То же в `ProjectorPreviewWindow.axaml` (`#111`, `#333`).

- Нет ни одного `StaticResource`/`ThemeResource` для цвета. Изменение акцента = поиск-замена по файлу.
- `App.axaml:5` объявляет `RequestedThemeVariant="Default"`, то есть тема следует за системной.
  При светлой теме Windows получаем светлый Fluent-хром (`TextBox`, `ComboBox`, `TabControl`,
  `ListBox`) поверх намертво тёмных панелей `#E61E1E1E` — нечитаемая мешанина.
- Фон панелей полупрозрачный (`#E6…` = 90%), поверх произвольного содержимого канваса. Контраст
  текста становится недетерминированным.
- `#666` на `#1E1E1E` даёт коэффициент контраста **2.9:1** — ниже WCAG AA (4.5:1). Используется для
  отправителя в логах (`:766`) при `FontSize="10"`.
- Отступы и радиусы тоже хардкод: `Margin="12"`, `Padding="12"`, `Spacing="6"`/`"8"`,
  `CornerRadius="4"`/`"3"`/`"2"` вперемешку.

### 1.6. Мусорный текст под вкладками сцен

`MainWindow.axaml:96-104` — `TabControl ItemsSource="{Binding Scenes}"` без `ContentTemplate`.
`ProjectionScene` (`CadProjector.Core/Scene/ProjectionScene.cs`) не наследует `ViewModelBase`,
поэтому `ViewLocator.Match` (`ViewLocator.cs:33-36`) возвращает `false`, и Avalonia рендерит
контент вкладки дефолтным шаблоном — то есть строкой `ToString()`. `ProjectionScene` не
переопределяет `ToString()`. Под полосой вкладок печатается
`CadProjector.Core.Scene.ProjectionScene` и `DockPanel` под неё выделяет высоту.

### 1.8. Прочее

- **Нет статус-бара.** Статус, состояние связи, прогресс и логи размазаны по тулбару и оверлеям.
- **Чип связи продублирован** двумя `TextBlock` с взаимоисключающими `IsVisible` (`:53-58`) —
  разница только в цвете и жирности. Это работа одного конвертера или стиля.
- **Иконочные кнопки без подписей и без hotkey-подсказок:** `↶`, `↷`, `+`, `−`, `✕`, `↑`, `↓`,
  `…`, `X`, `↻`. У части есть `ToolTip`, у части (`"X"` на `:617`, `"…"` на `:552`) — нет.
- **Нет `AutomationProperties`** ни на одном контроле; нет `MinWidth`/`MinHeight` у окна.
- **Нет визуальной иерархии внутри панелей:** заголовок секции и подпись поля отличаются только
  цветом (`#AAA` vs `#888`) при одинаковом размере шрифта.
- **Форма «label сверху / поле снизу»** размножена десятки раз копипастой; в панели устройств
  местами `DockPanel` с меткой слева (`:466-476`) — две разные раскладки в одной панели.

## Часть 2. Целевой дизайн

### 2.1. Принцип

Отказаться от «плавающих оверлеев поверх канваса» в пользу **классической оболочки CAD-редактора**
с закреплёнными зонами. Плавающая панель уместна, когда она одна; когда их десять — нужны слоты.

Ключевые правила:

1. **Один слот — одна активная панель.** Наложение становится структурно невозможным.
2. **Канвас никогда не перекрывается.** Панели отбирают место у канваса, а не ложатся поверх.
3. **Каждая команда живёт в одном месте.** Дубли убираются, остаётся один канонический путь.
4. **Всё, что рисуется, берёт цвет из токена.** Ни одного литерала цвета во вьюхах.

### 2.6. Менеджер панелей

Всё состояние `IsXOpen` (10 булевых полей в `MainViewModel`) заменяется одним объектом:

```csharp
public enum DockSlot { Left, Right, Bottom, Dialog }

public enum PanelId
{
    Objects, Scene, WorkFolder,          // Left
    Transform, Device, StlAlign,         // Right
    Logs, Endpoints, Clients, Commands,  // Bottom
    Hotkeys                              // Dialog
}

public sealed partial class WorkspaceViewModel : ViewModelBase
{
    [ObservableProperty] public partial PanelId? ActiveLeft { get; set; }
    [ObservableProperty] public partial PanelId? ActiveRight { get; set; }
    [ObservableProperty] public partial PanelId? ActiveBottom { get; set; }
    [ObservableProperty] public partial double LeftWidth { get; set; } = 300;
    [ObservableProperty] public partial double RightWidth { get; set; } = 340;
    [ObservableProperty] public partial double BottomHeight { get; set; } = 200;

    [RelayCommand] private void Toggle(PanelId id) { /* открыть/закрыть в своём слоте */ }
    [RelayCommand] private void CloseSlot(DockSlot slot) { /* Esc / крестик */ }
    public void Reveal(PanelId id) { /* программное открытие, напр. при выделении объекта */ }
}
```

Старые свойства `IsTreeOpen`, `IsSceneOpen`, … остаются как вычисляемые прокси
(`public bool IsTreeOpen => Workspace.ActiveLeft == PanelId.Objects`) на время миграции — так фазы
